# claude-discord 1.11.0 read-only TUI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `claude-discord tui` becomes a read-only, three-tab view (Bots, Alerts, Configuration) drawn as the approved mocks, showing for every bot its status, host, channel, who it receives from and when it last got a message.
**Architecture:** `health --json` gains four fields per bot (`channel`, `channel_name`, `last_message_at`, `access`) out of the jq calls it already makes; the monitor's reducer carries them into `state.json`, reads an optional `name=<display>` ledger word, and keeps in `alerts` the reason and text of every post plus the findings it does not post when they appear. `tui/claude_discord_tui.py` stays one file: pure functions turn the state into fixed-width `rich.text.Text` lines (tested with no terminal), and a small Textual shell (title line, tab row, one scrolling pane with a row cursor, footer) shows them.
**Tech Stack:** bash (3.2-compatible: macOS `/bin/bash`), jq (1.6 on the slower machine), perl, curl; Python 3.9+ with Textual `>=8.2.8,<9` and rich through `uv run --script` (TUI only); the stub-only suite `test-claude-discord.sh` and the pilot tests `tests/tui/test_tui.py`.
**Spec:** docs/superpowers/specs/2026-10-12-tui-redesign-hosts-access.md (section 1.11.0)

## Global Constraints

- **Scope.** Only the spec's "1.11.0: read-only redesign", "Owners' requirements" and "Constraints". 1.12.0 (hosts management: the `hosts` CLI, `host-id`, `+ Add host`, the `a`/`x`/`l` keys, the per-host popup, ssh config parsing), 1.13.0 (access and token editing, the `e` key), the `f`/`F` fix keys and the manager band are out: no task implements them and nothing is built "for later". The TUI writes nothing but its own holder record.
- **Execution is native:** one implementer session does Tasks 1 to 9 in order, each ending in a commit with its tests passing; then ONE deep review of the whole branch (`git diff main...feat/tui-1.11.0`). No parallel tasks. The review is by a separate review agent, junyong-dev-bot verifies on lmd42, and the diff summary goes in thread 1559286847446982770 before main (spec, Constraints).
- **Suite:** `./test-claude-discord.sh ./bin/claude-discord` stays under 40 s wall, run serially, stubs only (no real claude, `claude -p`, `--bg`, network or Discord). It sits at about 28 s on lmd79 and 31.5 s on the slower reference machine. Every task that adds suite cases states the seconds it adds; the total added by this plan is under 3 s (Task 1: 0.3 s measured; Tasks 2 and 3: under 0.1 s each, no new monitor pass and no new health run). TUI behaviour is tested in `tests/tui/test_tui.py`, never in the suite.
- **bash 3.2:** `bin/claude-discord`, `monitor/monitor.sh` and everything under `hooks/` must parse and run under macOS `/bin/bash` 3.2: no `${var,,}`, no `mapfile`, no associative arrays, no `case` inside `$(...)` with unbalanced parentheses, no quoted jq program inside `"$( )"` inside double quotes. `monitor/monitor.sh` has no here-document and no here-string (`<<`) at all. The suite itself is Linux-only.
- **jq starts:** a jq start costs 10 ms on machines with jq 1.6. No new jq call on a per-prompt or per-tick path; the new health fields come from jq calls that already run (the per-bot `cfg` read, the one read of `GET channels/<id>`, the final per-run call). The monitor still runs one reducer and at most one `apply` per pass.
- **A comment inside the monitor's `reduce='…'` and `apply='…'` jq programs holds no apostrophe:** each program is one single-quoted shell string, and an apostrophe ends it (found while writing this plan: `bash -n` fails far from the cause).
- **Older hosts:** an older claude-discord on a remote host returns JSON without the new fields. The monitor stores `null` for them and the TUI renders `-`; neither fails a pass or a refresh. The same holds for a `state.json` last written by a 1.10 monitor.
- **Secrets:** the TUI never reads a `.env` and never shows a token. No token in `state.json`, `monitor.log`, the TUI or a message. Of a ledger `KEY=VALUE` word only the key name reaches `state.json` (a proxy URL may hold a password).
- **No OS scheduler** (no launchd, systemd or cron).
- **Style:** code and comments in English; match the surrounding style (long lines and dense why-comments are the house style in the shell files). Minimum code: no abstraction for single use, no configurability nobody asked for. Labels in the TUI are English.
- **HARD HOME RULE** (from `CLAUDE.md`): any probe outside the test suite sets a literal sandbox `HOME` in the SAME Bash call, chained with `&&`; never write the real `~/.claude.json`, `~/.claude`, `~/.claude-discord` or `~/.local/bin`. Do not start the real TUI, a real monitor or a `claude` session to "see" a change: the pilot tests and the suite are the checks.
- **Commits:** by path only (`git add` new files first, then `git commit -m … -- <paths>`), on branch `feat/tui-1.11.0`, with no `Co-Authored-By` line. Do not push to `main`.

## Review Focus

Most likely to bite a user first. Each line names the test that pins it; a reviewer should see that test fail when the fix is reverted.

1. **A host on an older claude-discord, or a state written by an older monitor.** Two owners upgrade their machines on different days, so this happens on the first day. The host's document has no `channel`, `channel_name`, `last_message_at` or `access`; a 1.10 state has no `monitor.lang`, no host `display`/`env`/`hostname` and `alerts` records with no `detail`/`text`. 2. **A terminal under 110 columns and under 24 rows.** The default terminal is 80×24 and the mocks are 137 wide. The KPI band must fold to one line, `project` and `receives` must fold away, title, tab row and footer must stay one line each, and the row cursor must scroll its row into view. Pinned in Task 5 (pilot case `narrow`, a 100×20 terminal with 25 bots: `ok: narrow`) and Task 4 (`columns()` fits every width from 80 to 200; `kpi_lines(s, 109)` is the one line).
3. **Hangul and CJK in names and channel names.** A Hangul character is two terminal cells, so `len()` and `ljust()` shear every column to its right. The owners write Korean. Pinned in Task 4 (`ok: fit gives exactly the column's cells for ASCII, Hangul and CJK …` and `ok: the Bots table: one width for every line at 137 and 100 columns …`, which checks that the status and host columns start at the same cell after a Hangul bot name and channel name), Task 1 (suite: a channel named `봇 dev` is cached and reported as `봇-dev`; a space would have broken the four-word cache line) and Task 2 (suite: `name=람다` is the display name).
4. **An expanded allowFrom names list longer than its column.** A dev-manager's channel lists every peer bot. The names must fold inside the receives column over at most three lines and count the rest as `+N`, never push the `last` and `project` columns out. Pinned in Task 4 (`ok: names fold over at most three lines of the column and the rest is counted (+N); a name wider than the column is cut`) (the same test opens every row at 137 and at 100 columns and checks that all lines keep one width) and Task 6 (pilot case `bots`: the opened row shows `from dongyong22, gpuvillain,`).
5. **A bot with no token and no channel.** A bot set up with "register later" has an empty `.env` and no channel: it must be a `○ no token` row with dashes, counted apart, never a problem, and its health run must cost no Discord call. Pinned in Task 1 (suite: `ok: health --json carries … and empty or null ones for a bot with no token and no channel`) and Task 4 (the `NOTOK` row renders `-` in channel and receives, closed and open; `kpi()` counts it in `notoken`, not in `problems`).

## Names and fields this plan adds

Later tasks rely on these exactly.

**`health --json`, each bot object** (Task 1; also `.projects[].bots[]` of `health --all --json`):

| field | type | value |
|---|---|---|
| `channel` | string | the bot's channel id; `""` when it has none |
| `channel_name` | string | the channel's name, spaces and control characters made `-`; `""` when not known |
| `last_message_at` | string or null | `YYYY-MM-DDTHH:MM:SSZ`, the time inside `<bot>/last-message-id`; null when there is none |
| `access` | object or null | `{"dm": string or null, "dm_allow": [id…], "groups": [{"id": id, "mention": bool, "allow": [id…]}…]}`; an id is a string of digits; null when `access.json` cannot be read as one |

`<bot>/channel-guild` becomes one line of four words: `<channel id> <guild id> <name or -> <read at, epoch seconds>`.

**`state.json`** (Tasks 2 and 3):

| path | type | value |
|---|---|---|
| `hosts.<host>.display` | string | the ledger's `name=` word; `""` when none |
| `hosts.<host>.env` | [string] | the key names of the ledger's `KEY=VALUE` words, as written |
| `hosts.<host>.hostname` | string | the host's own `uname -n` (the document's `host`); set once a document was read, kept after |
| `bots.<key>.channel`, `.channel_name`, `.last_message_at`, `.access` | as above, or null | null when the host's document has no such field |
| `monitor.lang` | `"ko"` or `"en"` | the alert language of this pass |
| `monitor.owner_id` | string | `DISCORD_USER_ID` of the manager project's `config.env`; `""` when none |
| `alerts[]` | object | `{ts, key, kind: "finding" or "recovery", verdict, status: "sent" or "failed" or "not_posted", detail}`; a sent record also has `text` (the posted content, or null) and, when the record before it for that key is a failed one, `retried: true`. The last 100 are kept |

**`tui/claude_discord_tui.py`** (Tasks 4 to 8): constants `BRAND WARN OK ALERT BAR TAB CURSOR DIM DASH WIDE TABS PROBLEM GOOD WORD`; functions `epoch ago hhmm fit wrap fold_names rank mark host_label sorted_bots kpi kpi_lines columns channels receives row_lines bots_items` (Task 4), `open_alerts render title_line tabs_lines foot_line bar_text` (Task 5), `load_names entry_text` (Task 6), `key_parts kind posted_text rule alerts_items` (Task 7), `config_items` (Task 8); classes `Pane`, `MonitorTUI` (Task 5), `Detail` (Task 6), `Confirm` (kept). Widget ids: `#title #tabs #bar #pane #body #foot`, and `#body-detail #fix` on the Detail screen. An "item" is a tuple `(row key or None, [Text, …])`: a key makes its lines one row the cursor can sit on.

## Where the spec, the mocks and the code disagree, and what this plan does

1. **`mock-config.png` draws 1.12.0 controls** (`+ Add host`, `x remove (asks) · l laptop on/off`, footer keys `a`, `x`, `l`). The spec says "Configuration tab (read-only in 1.11.0)". Not built: the Configuration footer is `←→ tabs  ↑↓ select  enter all fields  q quit`.
2. **The mock's ssh target** is `dykim@wmac.example:22 (SECA2033001362)`. User, real host name and port come from parsing `~/.ssh/config`, which is 1.12.0. 1.11.0 shows the ledger's ssh name and, in parentheses, the machine's own hostname from its health document: `wmac (SECA2033002083)`; `this machine (local name=lmd79)` for `local`, as drawn.
3. **`stuck` in the spec's order list is no verdict** (`bin/claude-discord:1534` knows `stale`). `stale` is shown as `✕ STUCK` and ordered with the problems; the other words are `throttled` → `rate-limited`, `busy` → `working`, `unknown` → `no token`, `apierror` → `api error`, `nostate` → `no state`.
4. **"warning only".** The spec has `not posted (warning only)` and the mock a History row `rate-limited (HTTP 429); warning only — not posted`, but `throttled` IS posted once it has held 30 minutes (`monitor/monitor.sh:524`, the `hold` table). Rule used: the pass that first sees a finding records it in `alerts` as `not_posted` when the channel is not told at that moment by rule: no hold entry (`noreach`), a laptop's `hostdown`, or a hold of 30 minutes (`throttled`, `apierror`, `hostdown`). If it then holds, it is posted and gets a second record, `sent`. An opened bot row says `not posted (warning only)` when such a record exists for its verdict, `posted Nm ago` when posted, and `not posted yet` for a problem still inside its 5 minute hold. `not posted yet` is a third wording the spec does not list.
5. **The History "what" column** is the monitor's `detail` verbatim (the mock abbreviates it and appends `; warning only` / `· laptop, so not posted`; the `post` column already says so). A recovery's is `back after Nm`, written by the monitor when it posts.
6. **`✓ sent on retry`** is a post whose previous record for the same key is a failed one (it went out on a later pass). A 429 waited out inside one pass is a plain `✓ sent`. So that this reads cleanly, a POST that keeps failing is now ONE `alerts` record, not one per pass: a behaviour change in `state.json`, tested in Task 3.
7. **`alerts` keeps 100 records, was 50** (`monitor/monitor.sh:705`): not-posted records roughly double the rate, and the History rule shows 24 hours.
8. **The fix line's hint.** The spec says the hint is `c copies it` and "at < 110 columns the hint says only `c copies it`"; the mock draws `c copies it` at 137 columns too. One line at every width: `fix  <command>   c copies it`, never wrapped or cut by the TUI (the pane clips it at the terminal's edge); `c` copies the whole command and `Enter` shows it whole.
9. **`-` and `—`.** A value the state does not have renders `-` (the brief; the mocks draw `—`). The post column keeps the spec's literal `— not posted`.
10. **Kept though no mock shows them:** `Q` (quit and stop the backend, after a yes), the dialog when the TUI is opened after `monitor --stop`, and the red bar (now only for what the title's one status cannot say). They are 1.10.3 behaviour nobody asked to remove. Gone: the `a` key (the Alerts tab replaces that screen). The monitor's pid, its holders and the pass seconds are in no view any more (spec: "Removed from the default view"); the pid still appears in the red bar when it is gone.
11. **Other channels have no name.** health caches the name of the bot's main channel only (spec: "a third field of `channel-guild`"), so an opened row lists the other channels of its `access.json` as `#<id>`. `#bot-health-check (write-only)` is added to the manager bot's own row only: it is the one bot that posts there (`monitor/monitor.sh:49`).
12. **Names** come from the `user-names` files of the bots on this machine (`hooks/turn/on-prompt:81` writes `<id> <name>`); a remote bot's file is out of reach, so its ids get a name only when that person also wrote to a local bot.
13. **`channel-guild` gets a fourth field** (when the line was read, epoch seconds) beside the spec's third: the day is then known with no `date -r` fork per bot per run. A line an older version wrote (two fields) is read again once.
14. **`unknown` is "no token or channel"** (`bin/claude-discord:1426`). The row says `○ no token` either way, as the mock; the opened row's reason says which.
15. **`Open N`** is every host and bot entry with `posted` set in `state.json`, not a walk over `alerts`: exact, and it survives the 100-record cap.
16. **The spec's `mock.py` and `render.sh`** ("beside this file") are not in the repo; only the three PNGs are. The PNGs were the reference.

def fit(s: str, w: int) -> str:
    """`s` in exactly `w` terminal cells (a Hangul or CJK character takes two): padded, or cut with an ellipsis."""
    if cell_len(s) <= w:
        return set_cell_size(s, w)
    return set_cell_size(s, w - 1) + "…" if w > 0 else ""


def wrap(s: str, w: int, n: int) -> list[str]:
    """`s` broken at spaces into at most `n` lines of `w` cells; what is left over stays on the last one (fit cuts it)."""
    lines, cur = [], ""
    for word in s.split():
        if cur and cell_len(cur) + 1 + cell_len(word) > w and len(lines) < n - 1:
            lines.append(cur)
            cur = word
        else:
            cur = f"{cur} {word}" if cur else word
    return lines + [cur] if cur else lines


def fold_names(label: str, names: list, w: int, n: int = 3) -> list[str]:
    """`label a, b, c` on at most `n` lines of `w` cells; the names with no room left are counted: `+2`."""
    lines, cur = [], label
    for i, name in enumerate(names):
        rest = len(names) - i - 1
        if cell_len(name) > w - 4:   # one name wider than the column: cut, so it still gets a line
            name = fit(name, max(w - 4, 1)).rstrip()
        piece = name + ("," if rest else "")
        while True:
            last = len(lines) == n - 1
            room = w - (cell_len(f" +{rest}") if last and rest else 0)
            if cell_len(cur) + (1 if cur else 0) + cell_len(piece) <= room:
                cur = f"{cur} {piece}" if cur else piece
                break
            if last or not cur:
                return lines + [f"{cur.rstrip(',')} +{rest + 1}".strip()]
            lines.append(cur)
            cur = ""
    return lines + [cur]

def open_alerts(state: dict) -> list[dict]:
    """What the channel was told and has not seen recover: every entry with `posted`, as an alerts record (with the text
    of the last finding sent for its key, when that record is still kept), newest first."""
    out, alerts = [], state.get("alerts") or []
    for scope in ("hosts", "bots"):
        for k, e in (state.get(scope) or {}).items():
            if e.get("posted") and e.get("left_s") is None:
                key = k + "|-" if scope == "hosts" else k
                out.append({"ts": e.get("posted_at"), "key": key, "kind": "finding", "verdict": e["posted"], "status": "sent", "detail": e.get("detail", ""),
                            "text": next((x.get("text") for x in reversed(alerts) if x.get("key") == key and x.get("kind") == "finding"
                                          and x.get("status") == "sent"), None)})
    return sorted(out, key=lambda a: a.get("ts") or "", reverse=True)


def render(items: list[tuple], cursor: str | None, width: int) -> tuple[Text, int, int]:
    """The pane's text, and the first line and height of the cursor's row (highlighted to the edge)."""
    out, at = [], (0, 1)
    for key, lines in items:
        if key is not None and key == cursor:
            at = (len(out), len(lines))
            lines = [l.copy() for l in lines]
            for l in lines:
                l.pad_right(max(0, width - l.cell_len))
                l.stylize(f"on {CURSOR}")
        out += lines
    return Text("\n").join(out), at[0], at[1]


def title_line(state: dict, width: int, now: float, live: bool, stopped: bool) -> Text:
    """`◆ claude-discord  <manager>` and, on the right, the backend's status: symbol + word + colour."""
    m, mgr = state.get("monitor") or {}, state.get("manager", "?")
    left = Text.assemble(("◆ claude-discord", f"bold {BRAND}"), ("  " + mgr, DIM))
    due = epoch(m.get("next_pass"))
    if stopped or m.get("stopped_by_user"):   # monitor --stop: nothing starts it until monitor --start
        right = Text.assemble(("○ stopped by you", "bold"), ("  start: ", DIM), (f"claude-discord monitor --start {mgr}", BRAND))
    elif not live:
        right = Text("○ not running", DIM)
    elif due is not None and now - due > 30:   # more than one tick (30 s) past the pass that was due
        right = Text.assemble(("▲ check overdue", f"bold {WARN}"), (f"  due {hhmm(due)} · now {hhmm(now)}", DIM))
    else:
        checked = ago(m.get("last_pass"), now)
        nxt = max(0, int(due - now) + 59) // 60 if due is not None else None
        right = Text.assemble(("● live", f"bold {OK}"), ("  " + " · ".join(
            (["keeper"] if any(h.get("kind") == "keeper" for h in m.get("holders") or []) else [])
            + ([f"checked {checked} ago" if checked != "now" else "checked just now"] if checked else ["not checked yet"])
            + ([f"next {nxt}m"] if nxt is not None else [])), DIM))
    if left.cell_len + 2 + right.cell_len > width:   # a narrow terminal: the status alone, cut at the edge
        right.truncate(width, overflow="ellipsis")
        return right
    return Text.assemble(left, " " * (width - left.cell_len - right.cell_len), right)

def bar_text(state: dict, note: str = "", stopped: bool = False, refused: bool = False) -> str | None:
    """The red bar's text (None when there is nothing to warn about): what the title's one status cannot say. `note` is
    why `monitor --ensure` failed, when it did: the one place a refusal is visible. `stopped`: the `stopped` marker
    (monitor --stop) stands; the title says so. `refused`: this side's `refused.<pid namespace id>` marker (a detached
    start met a monitor lock this side cannot see; a start that gets through clears it) stands."""
    m = state.get("monitor") or {}
    pid = m.get("pid")
    bar = None
    if not state:
        bar = "no state yet: the monitor has not written state.json"
    elif stopped or m.get("stopped_by_user"):
        pass
    elif refused:   # held until a start gets through (monitor --start), like the stopped marker
        bar = (f"auto-start refused here: another side holds the monitor lock (shared home?). "
               f"Start here with: claude-discord monitor --start {state.get('manager', '?')}")
    elif not pid:
        bar = f"monitor stopped at {m.get('stopped_at') or '?'}"
    elif not alive(pid, state.get("manager") or ""):   # killed without its trap (kill -9, OOM): its pid stays in state.json
        bar = f"monitor pid {pid} is gone"
    elif m.get("error"):   # the last pass could not be folded into the state: nothing in it is current
        bar = f"the last pass failed: {m['error']}"
    elif m.get("post_failed"):
        bar = "the last POST to #bot-health-check failed; it is retried next pass"
    if note:
        bar = f"{bar}; {note}" if bar else note
    return bar

def load_names(state: dict) -> dict:
    """id -> display name, from the `user-names` file of every bot on this machine (written by on-prompt: `<id> <name>`).
    A remote bot's file is out of reach, so its ids get a name only when that person wrote to a local bot too."""
    names = {}
    for b in (state.get("bots") or {}).values():
        if b.get("host") != "local" or not b.get("bot") or not b.get("project"):
            continue
        try:
            text = (Path(b["project"]) / ".claude" / "discord-agents" / b["bot"] / "user-names").read_text(errors="replace")
        except OSError:
            continue

            if uid.isdigit() and name:

def key_parts(key: str) -> tuple[str, str]:
    """(host, bot) of an alerts key: `host|-` is the host itself, `host|project|-` a project with no bot known."""
    parts = key.split("|")
    return parts[0], (parts[-1] if len(parts) > 2 else DASH)


def kind(a: dict) -> tuple[str, str]:
    if a.get("kind") == "recovery":
        return "✓ recovered", OK
    if a.get("key", "").count("|") == 1:
        return "○ host", DIM
    return ("✕ down", ALERT) if rank(a.get("verdict", "")) == 0 else ("▲ check", WARN)


def posted_text(a: dict) -> str:
    """The text of an alerts record's post, or why there is none."""
    if a.get("status") == "not_posted":
        return "(not posted: a warning only, or still inside its hold time)"
    return a.get("text") or "(the text was not recorded: posted by a monitor older than 1.11.0)"


def rule(name: str, count: int | None, note: str, width: int) -> Text:
    """A rule heading: the name in brand, a dim count, a rule to the edge, a dim note on the right."""
    left = Text.assemble((name, f"bold {BRAND}"), (f" {count}" if count is not None else "", DIM), " ")
    right = Text.assemble(" ", (note, DIM)) if note else Text()
    return Text.assemble(left, ("─" * max(0, width - left.cell_len - right.cell_len), TAB), right)


def alerts_items(state: dict, width: int, now: float) -> list[tuple]:
    """The Alerts tab: Open (posted, not recovered) and History (the alerts records of the last 24 h, newest first)."""

    cols[-2] = ("what", max(10, width - 2 - sum(w for _, w in cols) - len(cols) + 1))

    def row(a: dict, bold: bool) -> list[Text]:
        t, (host, bot) = epoch(a.get("ts")), key_parts(a.get("key", ""))
        word, style = kind(a)
        post = ("✓ sent on retry", WARN) if a.get("retried") else ("✓ sent", OK) if a.get("status") == "sent" else ("— not posted", DIM)
        cell = {"when": [(f"{hhmm(t)} · {ago(a.get('ts'), now) or DASH}", "" if bold else DIM)],
                "": [(f" {word.upper()} " if bold else word, f"bold #000000 on {ALERT}" if bold and style == ALERT else style)],
                "bot": [(bot, "bold" if bold else "")], "host": [(host_label(state, host), DIM)], "what": [(a.get("detail") or DASH, "")], "post": [post]}
        return row_lines([(cell[n], w) for n, w in cols])

    opened = open_alerts(state)
    # A failed POST is retried next pass (the red bar says so); only what went out, or was never due to, is history.
    hist = [(i, a) for i, a in reversed(list(enumerate(state.get("alerts") or []))) if isinstance(a, dict) and a.get("status") != "failed"

    items: list[tuple] = [(None, [rule("Open", len(opened), "posted and not recovered yet", width), Text()]), head]
    items += [(f"open {a['key']}", row(a, True)) for a in opened]
    items += [(None, [Text(), rule("History", len(hist), "last 24 h · newest first · #bot-health-check", width), Text()]), head]
    items += [(f"hist {i}", row(a, False)) for i, a in hist]
    return items
