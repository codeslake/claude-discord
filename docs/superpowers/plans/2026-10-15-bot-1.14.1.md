## What this plan settles, and why

- **The version reaches the TUI as an argument**, not by the TUI running `claude-discord --version` itself: one process fewer at every TUI start, and the tests set it directly. `version_line()` prints exactly what `--version` prints today (`claude-discord <version> (<sha>|nogit)`): `hosts` and `access --host` parse that line on other machines, so its format does not move.
- **The title shows `◆ claude-discord 1.14.1 (8db5787)  <manager>`.** The sha is what `--version` shows; a TUI started without `--version-line` (the tests, an old wrapper) shows the title as today.
- **A rename is reflected from the CLI's last line**, `renamed: <old> -> <new>`, which 1.14.0 made the program-facing line precisely so a program could follow it. The row keeps its verdict and detail (they are the bot's, whatever its name) and loses its `≠ Discord` line (both names are the new one now: the CLI changed Discord first, or Discord had it already). The next pass's `state.json` replaces the whole state, as it does every pass.
- **M1 is wording.** The CLI's plan text already says "with no handoff.md: an empty context that catches up from the channel"; the README said "from its `handoff.md`" as if that were the norm. The README and the plan line now say what happens; no busy check (the owner: A).
- **M2: nothing is restarted** when one of several sessions will not stop: a start beside a session that still runs puts two sessions on one token (the very thing `stop_sessions` guards). The stopped ones are named with the command that starts one.
- **M4's re-check** is placed right after the answer and before `setup`: the only window a human leaves open. The test drives it through the pty driver's new field (a command run when the question is seen), so no sleep and no race in the suite.
- **M6a (`curl -q`) is not done:** a `~/.curlrc` with `trace` is the user's own file on the user's own machine; `-q` would also change every `curl` argv the suite asserts on. **M6c** (a `.env.cd.$$` left by SIGKILL between write and `mv`, mode 600, microseconds) is accepted. **M6d** is accepted by 1.14.0's decision 2. **M6e**: the test exists if `tests/tui/test_tui.py` asserts the `bytearray` is zeroed after Cancel and esc; add it if not.
- **M7a (the 4004 listener attached before `login`) is deferred:** it changes the patched `server.ts`, so every bot's plugin would be re-patched and the suite's patch-upgrade cases would grow by one generation; Discord rejects a reset token at `GET /gateway/bot` before any 4004 can arrive, so the window is theoretical. Noted in the spec's status for the next plugin-patch release.
- **M9**: the Mac `bash -n` check is part of this release's verification (it passed for 1.14.0); bash 3.2's `read` after a trapped SIGINT stays unverified (no 3.2 here). **M10**: the peer ran jq 1.6 on lmd42 for 1.14.0 (`ALL PASS`); the implementer runs it here too.

### Task 2: a rename shown at once

**TUI.** `MonitorTUI.renamed(host: str, project: str, old: str, new: str)`:

```python
def renamed(self, host: str, project: str, old: str, new: str) -> None:
    """`bot rename` moved a bot's directory (the CLI's last line): its row is the new name's now, without waiting
    for the pass the popup asked for. Both names are the new one, so the `≠ Discord` line goes. The next
    state.json replaces all of this."""
    bots = obj(self.state.get("bots"))
    for key in [k for k, b in bots.items() if isinstance(b, dict) and (txt(b.get("host")), txt(b.get("project")), txt(b.get("bot"))) == (host, project, old)]:
        b = bots.pop(key)
        b["bot"], b["discord_name"] = new, new
        nk = "|".join((host, project, new))
        bots[nk] = b
        if self.cursor["bots"] == key: self.cursor["bots"] = nk
        if key in self.opened: self.opened = (self.opened - {key}) | {nk}
    self.names = load_names(self.state)
    self.paint()
```

`BotName.ended`: when `RENAMED` matches, call `self.app.renamed(host, project, old, new)` with the entry's host and project first, then the existing `retarget` for the manager's own case. (Check the key form against `monitor.sh`'s reducer: `host|project|bot`; a remote bot's project is the path on that host, as the entry holds it.)
