# claude-discord 1.13.0 access editing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Who may drive a bot is read and changed with one command, `claude-discord access <bot> --json | set <change>...`, and from the TUI, which drives that command: `e` on a bot row opens an editor for the channels the bot listens in, per channel the mention rule and the senders, the DM policy with its allowlist, and the bot's mode. Bots on the manager's ledger hosts are edited the same way, over ssh.
**Architecture:** One new verb in `bin/claude-discord`. `--json` is read-only and needs no terminal: it reads `access.json` and asks Discord, with the bot's own token on the bot's own machine, for the server's channels, roles and members, and prints one line of JSON. `set` takes change words made of ids and fixed text only (`channel+<id>`, `mention:<id>=off`, `allow:<id>+<user>`, `dm=pairing`, `mode=dev-manager`, ...), prints what they would change, asks at the terminal (each widening change by itself, the rest once), and replaces `access.json` by rename under a lock, from the file as it is at that moment; the mode goes through the existing `setup <bot> --mode`. `--host <alias>` sends the same call to a ledger host as `~/.local/bin/claude-discord --version --access <hex project> <hex bot> ...` (an older remote prints its version line and does nothing else), with `ssh -t` when a question must be asked. `tui/claude_discord_tui.py` stays one file: pure functions turn the document into a model, the edited model into change words, and both into the editor's lines; one modal screen (`AccessEdit`) edits in memory and, on `s`, hands the terminal to `access ... set` with Textual's `App.suspend()`. The TUI never reads or writes `access.json`, never reads a `.env`, never holds a token.
**Tech Stack:** bash (3.2-compatible: macOS `/bin/bash`), jq (1.6 on the slower machine), perl (flock, the ssh cap), curl, ssh; Python 3.9+ with Textual `>=8.2.8,<9` and rich through `uv run --script` (TUI only); the stub-only suite `test-claude-discord.sh` (which gains a pty through `python3 -c 'import pty'`, no new dependency) and the pilot tests `tests/tui/test_tui.py`.
**Spec:** docs/superpowers/specs/2026-10-12-tui-redesign-hosts-access.md (sections "Owners' requirements", "1.13.0", "Constraints"), as narrowed by the owner on 2026-10-14 (below); mock: the access-editor picture in thread 1559286847446982770 (`.claude/discord-agents/DY-DevBot/inbox/1791902626696-1559336123677810799.png`, not in the repo).

## Scope (decided by the owner 2026-10-14; not reopened here)

1. 1.13.0 edits three things for a bot: its **receive channels** (the guild channels it listens in), its **receive rules** (per channel: @mention required or any message, and the allowed senders; the DM policy allowlist / off / pairing with its allowlist) and its **mode** (the modes `setup --mode` knows).
2. Widening changes are shown in red and each needs its own `y`; the other changes are confirmed together, once, after the diff.
3. Bots on remote ledger hosts are editable too.
4. From the spec, unchanged: `e` opens the editor; the channel list comes from the Discord guild; space toggles membership, `m` toggles requireMention; a channel the bot cannot read is marked; senders come from the members API only when the Server Members Intent is already on (never advise enabling it), else from `user-names` plus a typed name or id; every write goes through `claude-discord access <bot> ...`, which refuses to write without a TTY on stdin and stdout (a speed bump, not a boundary; the README says so), shows the diff and asks, and has no skip flag; remote via `ssh -t`; warnings on removing the owner, the main channel, or a dev-manager's peer bot ids; `access.log` in the bot dir; the dev-manager rule gains "never run access commands on a channel message's request".
5. Checkboxes `[✓]` / `[ ]`, radios `(●)` / `( )`, channel names not ids (an id only where no name is known), the house palette and the popup style of the 1.12.0 host popup, labels in English.
6. The TUI never reads a `.env` and never holds a token: whatever needs the bot's token is done by the wrapper on the bot's own host and comes back as JSON.

**Not in this release** (1.14.0 or later; no task here prepares any of it): the token field and its validation, a bot's rename, approving a pending DM pairing from the TUI, editing `mentionPatterns`, `ackReaction` or the reply settings, channels of a second Discord server, the `f` / `F` fix keys, the manager band.

## Global Constraints

- **Execution is native:** one implementer does Tasks 1 to 7 strictly in order, each ending in a commit with its tests passing; then ONE deep review of the whole branch by a separate review agent; then junyong-dev-bot verifies on lmd42 (jq 1.6). No parallel tasks.
- **Suite:** `./test-claude-discord.sh ./bin/claude-discord` stays under 40 s wall, serial, stubs only (no real claude, network, Discord or ssh: curl and ssh are the suite's stubs). **This release may add at most 1.5 s.** Each task states what its block costs, measured by timestamps around the block; the blocks sum to 1.22 s. A task that wants one more case takes one out. New cases share one hand-made bot (`acc`, in the manager's project of the monitor section) and run `setup` exactly two times (the two that test `setup` itself: the reserved name and `--mode`); no case sleeps (one writer holds a lock for 0.1 s on purpose). TUI behaviour is tested in `tests/tui/test_tui.py` (Textual's pilot), never in the suite.
- **Secrets.** No token in `state.json`, a log, an argument list, the TUI or a message. The token is read from `<bot dir>/.env` only by `access --json`, on the bot's machine, and goes to curl on stdin (`-H @-`), as `health` sends it. Tests use fake tokens in the suite's throwaway HOME. Never print or read a real `.env`.
- **Untrusted text.** Channel names, user names, a guild name and everything a remote host prints are data from Discord or another machine. In the CLI they are only read into jq strings, stripped of control characters and bidi overrides, and printed; none becomes a word of a command. On the wire to a remote host go hex digits, ids and change words only. In the TUI every string of the document passes `clean` before it is drawn, and every field is read through `txt` / `obj` / `seq`, so a wrong-typed document does not raise.
- **ssh.** A host reaches ssh only after `alias_re` and always after `--`; every call has `BatchMode=yes` and `ConnectTimeout=8`; every call that asks no question is capped (the 1.12.0 `h_ssh`) with stdin from `/dev/null`; the one call that asks (`ssh -t`) has no cap, because a person is answering.
- **bash 3.2:** `bin/claude-discord` must parse and run under macOS `/bin/bash` 3.2: no `${var,,}`, no `mapfile`, no associative arrays, no `case` inside `$(...)`, no single-quoted jq program inside `"$( )"` inside double quotes. The new code keeps every jq program in a single-quoted variable or argument outside any `"$( )"`.
- **jq:** functions of jq 1.6 only (`test`, `capture`, `sub`, `gsub`, `split`, `join`, `to_entries`, `from_entries`, `map_values`, `group_by`, `sort_by`, `any`, `all`, `inputs`, `reduce`, `error`, `try`, `tojson`, `fromjson`, `ascii_downcase`, `startswith`, `index`, `unique`). An id is never turned into a jq number (a snowflake does not fit a double): ids stay strings, and permission bit sets are picked out as text and combined by bash's 64-bit arithmetic.
- **No OS scheduler.**
- **Style:** code and comments in English; long lines and dense why-comments are the house style of the shell files. Minimum code: no flag, option or abstraction nobody asked for.
- **HARD HOME RULE** (from `CLAUDE.md`): any probe outside the suite sets a literal sandbox `HOME` in the SAME Bash call, chained with `&&`; never write the real `~/.claude.json`, `~/.claude`, `~/.claude-discord` or `~/.local/bin`, nor any `.env`. Do not start the real TUI, a real monitor or a `claude` session to "see" a change, and never run the real ssh against a host in a probe: the suite and the pilot tests are the checks.
- **Commits:** by explicit path, on branch `feat/access-1.13.0`, with no `Co-Authored-By` line. Never push to `main` from this plan's steps.

## Names this plan adds

Later tasks rely on these exactly.

**CLI** (`bin/claude-discord`):

```
claude-discord access [--project <dir>] <bot> --json
claude-discord access [--project <dir>] <bot> set <change>...
claude-discord access --host <alias> [--manager <bot>] --project <dir> <bot> --json | set <change>...
claude-discord --version --access <hex of the project> <hex of the bot> --json | set <change>...     (what --host runs there)

<change>:  channel+<channel id>            listen there: an @mention required, from the owner (DISCORD_USER_ID) alone
           channel-<channel id>            stop listening there
           mention:<channel id>=on|off     an @mention is required | every message is answered
           allow:<channel id>+<user id>    a sender is added to that channel's list
           allow:<channel id>-<user id>    ... taken off it (never the last one: an empty list is everyone)
           allow:<channel id>=any          anyone in the channel may write (an empty allowFrom)
           dm=allowlist|pairing|off        the DM policy; off is an allowlist with nobody on it
           dm+<user id>   dm-<user id>     the DM allowlist (whoever is on it also answers the bot's permission prompts)
           mode=none|dev-manager|autoresearchclaw     through `setup <bot> --mode`
```

A change word matches `a_word_re`:
`^(channel[+-][0-9]{1,20}|mention:[0-9]{1,20}=(on|off)|allow:[0-9]{1,20}([+-][0-9]{1,20}|=any)|dm=(allowlist|pairing|off)|dm[+-][0-9]{1,20}|mode=(none|dev-manager|autoresearchclaw))$` (in the C locale, `c_match`). The other shapes: an ssh alias is the 1.12.0 `alias_re` (`^[A-Za-z0-9._@][A-Za-z0-9._@-]{0,254}$`); a bot's name is a plain directory name (not empty, not `.` or `..`, no `/`), and on the wire `^([0-9a-f][0-9a-f]){1,255}$`; a project path on the wire is `^([0-9a-f][0-9a-f]){1,1024}$`; an id inside jq is `\A[0-9]{1,20}\z`.

**Exit status of `access`:** 0 done, or nothing to change; 1 it could not (no such bot, `access.json` unreadable or changed meanwhile, a failed write, the lock held 5 s, no manager's ledger for `--host`, or a 1.13.0 host that said why it could not); 2 usage, a word that is no change, a change that cannot be made; 3 no terminal: the changes were printed, nothing written; 4 answered no: nothing written; 5 `--host`: no answer from the host, or its claude-discord is older than 1.13.0.

**`access --json`** prints one line:

```
{"access": 1, "version": "1.13.0", "bot": str, "bot_id": str, "host": str, "project": str, "mode": str,
 "owner": "<DISCORD_USER_ID or empty>", "main": "<the bot's main channel id>", "peers": ["<peer bot id>"],
 "guild": {"id": str, "name": str} | null,
 "policy": {"dm": "allowlist"|"pairing"|"disabled"|..., "dm_allow": [id], "groups": [{"id": str, "mention": bool, "allow": [id]}]},
 "channels": [{"id": str, "name": str, "kind": "text"|"news"|"forum"|"unknown", "read": true|false|null}],
 "people": [{"id": str, "name": str, "bot": bool}],
 "members": "api"|"names", "errors": [str]}
```

`policy` has the shape of `health --json`'s `access`. `channels` is the guild's text (type 0), announcement (5) and forum (15) channels by position, then every group of the policy the guild did not list (`kind: "unknown"`, `read: null`). `read: null` means "cannot be told". `"access": 1` is the marker a caller looks for: an older claude-discord prints `claude-discord <version> (<sha>)` and no such line.

**The diff `access set` prints** (the first line, then one line per change, then the warnings):

```
claude-discord: access: <bot> on <hostname>, <path of access.json>
  ! #dev-bots: an @mention required -> any message                       a widening: red at a terminal, its own question
    #dev-bots: - gpu villain (222) may no longer write to it there       any other change: asked about together, once
warning: dongyong22 (111) is the owner of this bot ...                    yellow at a terminal; asks nothing more
```

and its questions: `<the widening's line>. Allow? [y/N] ` once per widening, then `Apply this change? [y/N] ` / `Apply these N changes? [y/N] ` (no widening before it) or `Apply the other change too? [y/N] ` / `Apply the other N changes too? [y/N] `. Only `y` or `Y` is yes.

## What this plan settles, and why

Each line is a decision with its reason. The six an owner is most likely to overrule are marked **(owner?)** and come with the alternative.

**The CLI**

1. **Changes are argument words made of ids and fixed text** (`allow:900+333`), not JSON and not stdin. Stdin must stay the terminal for the questions, so a change set cannot arrive there; a word a person can type is also a word the TUI can show before it runs, and its one regex is the whole quoting story for the remote path.
2. **`access <bot> set` writes; there is no `--yes`, `--force` or `--dry-run`.** Without a terminal the same call prints the diff and exits 3, which is the dry run.
3. **One `n` aborts everything (exit 4); nothing is written.** **(owner?)** Alternative: drop only the refused widening and apply the rest. Chosen because the file should be exactly what was shown and agreed to, never a third state nobody saw; and because in the TUI the edits stay on the screen after a no, so unticking the one change and saving again is two keys.
4. **What counts as widening** (asked about one by one): an @mention no longer required (also on a new channel); a channel opened to anyone; DMs to `pairing`; DMs back from the plugin's `disabled`; a person added to the DM allowlist; a person the bot listed nowhere until now (once, however many channels); leaving dev-manager when that deletes a hosts ledger. **Not** widening: taking a sender off, adding a channel for people the bot already lists (they could already drive it), a mention rule switched on, `dm=off`, any other mode change. **(owner?)** Alternative for "a known person on one more channel": ask about that too. Chosen as it is because the bot's shell is one shell: a person who can drive it in one channel gains no new power in a second one, and a question per person per channel would train the owner to press `y`.
5. **A person added to the DM allowlist is a widening even when they already write in a channel**, because the plugin sends the bot's tool-permission prompts to exactly that list and takes their answers (`server.ts`: `for (const userId of access.allowFrom)` in the permission handler, and the `interactionCreate` check).
6. **`dm=off` is an allowlist with nobody on it, not the plugin's `disabled`.** The plugin's `gate()` returns `drop` for `dmPolicy === 'disabled'` before it looks at whether the message is a DM, so `disabled` silences the guild channels too (its own ACCESS.md says so). A bot found in `disabled` is shown as such, and leaving it is a widening.
7. **`channel+<id>` starts closed:** an @mention required, from the owner alone (`DISCORD_USER_ID` of the project's `config.env`). With no owner id known it is refused. **(owner?)** Alternative: copy the main channel's rule and senders. Chosen because the smallest grant is the safe default and every step up from it is then a visible change.
8. **A removal never empties a sender list** (exit 2 with the two ways out): an empty `allowFrom` means everyone to the plugin, so "remove the last person" would silently mean "open to all". Only `allow:<id>=any` says that, and it is a widening.
9. **Names are shown, ids are stored and sent.** A person is printed as `name (id)`: a display name is the sender's to choose, and two people can share one. A channel is `#name`, or `#<id>` when no name is known.
10. **Atomic write, lock, and the plugin as a second writer.** The plugin (`~/.claude/plugins/cache/claude-plugins-official/discord/0.0.4/server.ts`, read for this plan) re-reads `access.json` on every inbound message (`loadAccess()` in `gate()`), so a change applies at the next message with no restart; it moves a file it cannot parse to `access.json.corrupt-<ms>` and continues with `{dmPolicy: "pairing", groups: {}}`; and it rewrites the file itself, through `access.json.tmp` and a rename and with no lock, when a DM asks for a pairing code, a code is re-sent or one expires. So: never write in place (temp file `access.json.cd.<pid>` beside it, `mv -f`); one writer of ours at a time (`flock` on `access.json.lock` through perl, as the ledger's); the new document is made by the same jq program from the file as it is at the moment of the write, so the plugin's `pending` entries and any unknown key are carried over; and the write is given up (exit 1) when the POLICY in the file is no longer the one the questions were about. What is left: the plugin writing in the milliseconds between our read and our rename loses that one pending pairing code (the sender is sent another on their next DM). The `/discord:access` skill edits `~/.claude/channels/discord/access.json` by its own text, not a bot's state dir, and reads before it writes; nothing here depends on it.
11. **Mode 600 always**, whatever the file was (the plugin writes 600 too), and `access.log` 600: both sit beside the token.

**The mode**

12. **`mode=` runs `setup <bot> --mode` with the mode on its stdin and nothing after it**, never a copy of its logic. `setup --mode` already refuses a bot that is not set up, reads one line for the mode without a terminal, keeps the peers and the hosts on an empty answer (EOF here), adds the peers of `peers.json` to every channel that lists its senders when the mode is dev-manager, writes the ledger with `local` for a new manager and starts its keeper, removes the ledger otherwise, and refuses a second manager of one name. `access` shows all of that BEFORE it asks: the peers `setup` will add are applied to the diff first (so a peer the bot never listed is a widening with its own question), entering dev-manager says `it gets a hosts ledger (this machine) and its monitor starts, which posts in #bot-health-check`, and leaving it with a ledger is asked about by itself: `mode: dev-manager -> <mode>: its hosts ledger (<path>) is deleted and its monitor and keeper stop within a minute. Nobody is told in #bot-health-check when a bot of its hosts goes down`.
13. **Does a running session need a restart for a new mode? No for the hooks, yes for the rule text.** Every hook reads `<bot dir>/mode` at each call (`hooks/lib/discord.sh`: `read -r bot_mode < "$DISCORD_STATE_DIR/mode"`), so `mention-guard`, `edit-gate`, `checkin`, `thread-guard` follow at their next call, and `on-prompt` re-primes the Discord-turn context because the mode is part of its key. The dev-manager rule text and the autoresearchclaw rule are given by SessionStart hooks: they reach, or leave, a running session at its next start, resume, compact or clear. The CLI prints exactly that after a mode change and the TUI repeats it.

**Remote hosts**

14. **`--host <alias>` is resolved against the manager's ledger by the CLI, which takes that line's env words itself** (as the monitor's pass does: a proxy word in both spellings, `name=` skipped). The TUI therefore never has an env value, and a person can type the same command. `--host local` runs here with the local line's env words, because a bot's Discord calls need the proxy the monitor's do.
15. **The remote command is `~/.local/bin/claude-discord --version --access <hex project> <hex bot> --json|set <words>`.** Behind `--version` for the reason 1.12.0's `--host-id` is: an older wrapper prints its version line and exits, where a new verb would be read as a bot's name and reach the launcher. Hex for the two strings that are not ours (a path, a bot's directory name): no quoting has to hold in a remote shell.
16. **What an older remote returns, and what the owner sees.** `--json`: the version line and no `{"access":1` line, so `claude-discord: access: wmac needs claude-discord 1.13.0 for this (it has 1.12.0; claude-discord update, there)`, exit 5; the editor opens, shows that line in the alert colour and offers nothing to edit. `set` asks the host's version first (one capped call) and never sends a change to an older one. A 1.13.0 host that could not do it (no such bot there) prints no version line: its last line is passed on (`claude-discord: access: wmac: no bot 'x' set up in ...`), exit 1.
17. **`--json` over ssh takes up to 4 MiB as it came** (`h_ssh ... raw`), where a probe's answer is cut to 4096 bytes and 200 characters a line: a server with hundreds of channels is one long line. The document is the last line that starts `{"access":` and parses with `.access == 1`; everything else the host printed is dropped.

**Whether the bot can read a channel**

18. **Computed from four answers, Discord's own order:** the permissions of `@everyone` (the role whose id is the guild's) and of the bot's roles, OR-ed; administrator (`1 << 3`) or guild owner reads everything; then the channel's overwrites: `@everyone`'s deny then allow, the bot's roles' denies then allows (all of them together), the bot's own deny then allow. Readable means `VIEW_CHANNEL` (`1 << 10`) and `READ_MESSAGE_HISTORY` (`1 << 16`) both set. jq only picks the numbers out as text; bash does the bit arithmetic.
19. **Unknowable is `null`, drawn `?`, never a guess:** a call that failed (the errors are listed in `errors`), no `@everyone` role in the answer, a permission that is not a number of at most 18 digits (bash arithmetic is 64-bit signed; today's permission sets are 16 digits), a group of the policy that the guild did not list (another server's channel, a deleted one). Limits that are NOT detected and are stated in the README: only the server of the bot's main channel is asked; a timed-out bot member; a channel the bot can read but not write in.
20. **Members:** `GET /guilds/{id}/members?limit=1000` answers only with the Server Members Intent on; any other status is not an error and nothing is advised. The people are then this machine's `user-names` and `peers.json` plus every id already on a list. In the TUI a person is added by a name that matches exactly one known person, or by a numeric id.

**The TUI**

21. **The editor edits in memory and saves with `s`; nothing is written while editing.** `s` builds the change words and hands the terminal over: `with self.suspend(): subprocess.call([wrapper, "access", "--host", <host>, "--manager", <manager>, "--project", <project>, "--", <bot>, "set", *words])`, then one `input()` so what the CLI printed stays until it was read. #   access <bot> set <change>... prints what would change, asks, writes. A change is a word a person can type, made of
#                                lower-case letters, digits and : + = - only (a_word_re), so it travels over ssh as it is:
#     channel+<channel id>  channel-<channel id>          listen there (an @mention required, from the owner alone) / stop
#     mention:<channel id>=on|off                         an @mention is required / every message is answered
#     allow:<channel id>+<user id>  allow:<channel id>-<user id>  allow:<channel id>=any    who may write there
#     dm=allowlist|pairing|off  dm+<user id>  dm-<user id>          DMs: off is an allowlist with nobody on it
#     mode=none|dev-manager|autoresearchclaw              through `setup <bot> --mode`, its questions answered by Enter
# A change that widens who can drive the bot (marked "!", red at a terminal) is asked about by itself; the others are
# confirmed together, once. Any "no" writes nothing: the file is what was shown and agreed to, or as it was.
# It refuses to write unless stdin and stdout are a terminal, and has no flag to skip the questions. That is a speed
# bump, not a boundary: whoever can run this can also edit the file. Without a terminal it prints the changes and exits 3.
# --project <dir>: the bot's project (default: the one above the cwd that has the bot).
# --host <alias>: the bot lives on a host of a manager's ledger (--manager <bot> when the project has several): `local`
# runs it here with that line's env words, any other alias over ssh with them (a question needs `ssh -t`, so a terminal
# here). Only hex digits, ids and change words go into the remote command; no name does.
# Exit status: 0 done, or nothing to change; 1 it could not (no such bot, access.json unreadable or changed meanwhile, a
# failed write, the lock held 5 s, no manager's ledger for --host); 2 usage, a word that is not a change, or a change
# that cannot be made; 3 no terminal: nothing written; 4 answered no: nothing written; 5 --host: no answer from the
# host, or its claude-discord is older than 1.13.0.

    # @everyone's and the bot's roles' permissions together; then the channel's overwrites, @everyone's first, the
    # roles' next (their denies, then their allows), the bot's own last. An administrator (1 << 3) and the server's

      [ "$1" != - ] || return 0
      for x in ${1//,/ }; do
        if a_num "${x%/*}" && a_num "${x#*/}"; then al=$((al | 10#${x%/*})) dn=$((dn | 10#${x#*/})); else unsure=1; fi
      done
      p=$(( (p & ~dn) | al ))
    }

    while read -r t a b c e; do
      case $t in
        B) for x in $a $b $c $e; do if a_num "$x"; then base=$((base | 10#$x)); else sure=no; fi; done;;
        O) [ "$a" != 1 ] || all=1;;
        C) p=$base unsure=0; a_ow "$b"; a_ow "$c"; a_ow "$e"
           if [ "$sure" != yes ] || ! c_match "$a" '^[0-9]{1,20}$'; then :
           elif [ "$all" = 1 ] || [ $((base & 8)) != 0 ]; then a_reads="$a_reads$a 1"$'\n'
           elif [ "$unsure" = 1 ]; then :
           elif [ $((p & 1024)) != 0 ] && [ $((p & 65536)) != 0 ]; then a_reads="$a_reads$a 1"$'\n'
           else a_reads="$a_reads$a 0"$'\n'; fi;;
      esac
    done <<<"$a_lines"

        --arg reads "$a_reads" --arg errs "$errs" --argjson policy "$a_p" "$a_defs"'

        | ([$mm | arrays | .[] | objects | select(.user | type == "object")
            | {id: (.user.id | tostring), name: (.nick // .user.global_name // .user.username // "" | safe), bot: (.user.bot == true)}]) as $api
        | ([$PL[] | . + {bot: true}] + [$UN | to_entries[] | {id: .key, name: .value, bot: false}]) as $kept
        | {access: 1, version: $ver, bot: $bot, bot_id: $me, host: $host, project: $project, mode: $mode,
           owner: (if ($owner | isid) then $owner else "" end), main: $main, peers: [$PL[] | select((.name | ascii_downcase) != ($bot | ascii_downcase)) | .id],
           guild: (if ($g | type) == "object" then {id: ($g.id | tostring), name: ($g.name // "" | safe)} else null end),
           policy: $policy,
           channels: ([$gc | sort_by(.position // 0)[] | {id, name: (.name // "" | safe), kind: (if .type == 15 then "forum" elif .type == 5 then "news" else "text" end), read: $R[.id]}]
                      + [$policy.groups[] | .id as $i | select(all($gc[]; .id != $i)) | {id: $i, name: ($CN[$i] // ""), kind: "unknown", read: null}]),
           people: (($api + $kept + [($policy.dm_allow + [$policy.groups[].allow[]])[] | {id: ., name: "", bot: false}])
                    | map(select(.id | isid)) | group_by(.id) | map(.[0] + {name: (map(.name | select(. != ""))[0] // ""), bot: any(.[]; .bot)})),
           members: (if ($mm | type) == "array" then "api" else "names" end),
           errors: ($errs | split("\n") | map(select(. != "")))}'
    }
    printf '%s\n%s\n%s\n' "$a_g" "$a_c" "$a_mm" | a_doc 2>/dev/null ||
      { errs="$errs${errs:+$'\n'}Discord's answer could not be read"; a_reads=""; printf 'null\nnull\nnull\n' | a_doc; }
    exit 0
  fi
fi

# `e` on a bot row. What the editor shows comes from `claude-discord access ... <bot> --json`, run on the bot's own
# machine (the token never leaves it); what it changes goes back as change words to `claude-discord access ... <bot>
# set`, which shows the changes on the terminal, asks, and writes. This program never reads or writes access.json.
MODES = ("none", "dev-manager", "autoresearchclaw")
DMS = ("allowlist", "off", "pairing")
DIGITS = re.compile(r"[0-9]{1,20}")


def access_model(doc: dict) -> dict:
    """What the editor changes, from the document's policy and mode: {"groups": {channel id: {"mention": bool, "allow":
    [user ids]}} in the document's order, "dm": allowlist | off | pairing | disabled, "dm_allow": [user ids], "mode"}.
    `off` is an allowlist with nobody on it (the plugin's own `disabled` drops every message, in the channels too). A
    value of the wrong type reads as missing; an id that is not digits is none."""
    pol = obj(obj(doc).get("policy"))
    digits = lambda v: [i for i in ids(v) if DIGITS.fullmatch(i)]
    dm, dm_allow = txt(pol.get("dm")), digits(pol.get("dm_allow"))
    return {"groups": {g["id"]: {"mention": g.get("mention") is not False, "allow": digits(g.get("allow"))} for g in groups(pol) if DIGITS.fullmatch(g["id"])},
            "dm": "disabled" if dm == "disabled" else "pairing" if dm != "allowlist" else "allowlist" if dm_allow else "off",
            "dm_allow": dm_allow, "mode": txt(obj(doc).get("mode")) or "none"}


def dm_word(m: dict) -> str:
    """The DM policy as it works: an allowlist with nobody on it is off."""
    return "off" if m["dm"] == "allowlist" and not m["dm_allow"] else m["dm"]


def access_words(was: dict, now: dict, owner: str) -> list[str]:
    """The change words (`claude-discord access <bot> set <word>...`) that turn the model `was` into `now`. A channel
    the CLI adds starts with an @mention required and the owner alone, so a new channel's words are what differs from
    that. Every word is made of an id and fixed text."""
    out = [f"channel-{c}" for c in was["groups"] if c not in now["groups"]]
    for c, g in now["groups"].items():
        old = was["groups"].get(c)
        if old is None:
            out.append(f"channel+{c}")
            old = {"mention": True, "allow": [owner] if owner else []}
        if g["mention"] != old["mention"]:
            out.append(f"mention:{c}={'on' if g['mention'] else 'off'}")
        if not g["allow"]:
            out += [f"allow:{c}=any"] if old["allow"] else []
        else:   # the additions first: a list is never empty on the way
            out += [f"allow:{c}+{u}" for u in g["allow"] if u not in old["allow"]] + [f"allow:{c}-{u}" for u in old["allow"] if u not in g["allow"]]
    a, b = dm_word(was), dm_word(now)
    if b == "off":
        out += ["dm=off"] if a != "off" else []
    else:
        out += [f"dm={b}"] if b != a and b != "disabled" and not (a == "off" and b == "allowlist") else []
        out += [f"dm+{u}" for u in now["dm_allow"] if u not in was["dm_allow"]] + [f"dm-{u}" for u in was["dm_allow"] if u not in now["dm_allow"]]
    return out + ([f"mode={now['mode']}"] if now["mode"] != was["mode"] else [])


def access_wide(was: dict, now: dict) -> set:
    """What of `now` widens who can drive the bot, drawn in the alert colour: `mention:<channel>` (an @mention no longer
    required), `any:<channel>` (anyone may write), `new:<user>` (a person the bot listed nowhere), `dm` (to pairing, or
    back from disabled), `dm:<user>` (added to the DM allowlist). The CLI decides the same on its own and asks about
    each; this is only what the screen shows before."""
    known = {u for g in was["groups"].values() for u in g["allow"]} | set(was["dm_allow"])
    out = set()
    for c, g in now["groups"].items():
        old = was["groups"].get(c)
        if not g["mention"] and (old is None or old["mention"]):
            out.add(f"mention:{c}")
        if not g["allow"] and (old is None or old["allow"]):
            out.add(f"any:{c}")
        if old is None or old["allow"]:
            out |= {f"new:{u}" for u in g["allow"] if u not in known}
    a, b = dm_word(was), dm_word(now)
    if a != b and (b == "pairing" or a == "disabled"):
        out.add("dm")
    return out | ({f"dm:{u}" for u in now["dm_allow"] if u not in was["dm_allow"]} if b != "off" else set())


def access_people(doc: dict, was: dict, now: dict, extra=()) -> list[dict]:
    """The people the right pane lists: everyone on a list of the bot, before or now, and `extra` (the ids typed into
    this editor), so one just added or just taken off stays in sight. Each is {"id", "name", "bot", "tag"}: people
    first, then bots, by name; no name is the id."""
    listed = {u for m in (was, now) for g in m["groups"].values() for u in g["allow"]} | set(was["dm_allow"]) | set(now["dm_allow"]) | set(extra)
    known = {p["id"]: p for p in seq(obj(doc).get("people")) if isinstance(p, dict) and isinstance(p.get("id"), str)}
    owner, peers = txt(obj(doc).get("owner")), ids(obj(doc).get("peers"))
    rows = [{"id": u, "name": txt(known.get(u, {}).get("name")) or u, "bot": known.get(u, {}).get("bot") is True,
             "tag": "owner" if u == owner else "peer bot" if u in peers else "bot" if known.get(u, {}).get("bot") is True else ""} for u in listed]
    return sorted(rows, key=lambda p: (p["bot"], p["name"].lower(), p["id"]))


def find_person(text: str, doc: dict) -> tuple[str | None, str]:
    """A typed name or id as a user id: (id, "") for digits, or for the one known person of that name (the whole name
    first, then a part of it; a leading @ is dropped); (None, why) for no one or for several."""
    t = text.strip().lstrip("@")
    if DIGITS.fullmatch(t):
        return t, ""
    people = [p for p in seq(obj(doc).get("people")) if isinstance(p, dict) and DIGITS.fullmatch(txt(p.get("id"))) and txt(p.get("name"))]
    hits = [p for p in people if p["name"].lower() == t.lower()] or [p for p in people if t and t.lower() in p["name"].lower()]
    if len(hits) == 1:
        return hits[0]["id"], ""
    if not hits:
        return None, "no one of that name is known here: type the numeric user id"
    return None, f"{len(hits)} people match: " + ", ".join(sorted(p["name"] for p in hits)[:5]) + (" …" if len(hits) > 5 else "")


def box(on: bool) -> str:
    return "[✓]" if on else "[ ]"


def radios(options: tuple, on: str, wide: bool = False) -> Text:
    """Radio choices on one line, drawn `(●) a   ( ) b`; the chosen one bold, in the alert colour when it widens."""
    out = Text()
    for o in options:
        out.append(f"{'(●)' if o == on else '( )'} {o}   ", (f"bold {ALERT}" if wide else "bold") if o == on else "")
    return out


def window(n: int, at: int, rows: int) -> range:
    """The `rows` indexes of `n` drawn around the cursor `at`."""
    top = max(0, min(at - rows // 2, n - rows))
    return range(top, min(n, top + rows))


def access_left(doc: dict, was: dict, now: dict) -> list[tuple]:
    """The left list's rows: ("ch", channel id) for each channel of the document, then ("dm", ""), ("mode", "")."""
    return [("ch", c["id"]) for c in seq(obj(doc).get("channels")) if isinstance(c, dict) and DIGITS.fullmatch(txt(c.get("id")))] + [("dm", ""), ("mode", "")]


def access_right(doc: dict, was: dict, now: dict, row: tuple, extra=()) -> list[tuple]:
    """The right list's rows for the left row the cursor is on: for a channel the bot listens in, ("u", user id) for
    each person and ("any", "") last; for the DMs row the people; nothing for a channel it does not listen in or the mode."""
    people = [("u", p["id"]) for p in access_people(doc, was, now, extra)]
    if row[0] == "ch" and row[1] in now["groups"]:

    return people if row[0] == "dm" else []

        note = ([("main", DIM)] if c == txt(doc.get("main")) else []) + ([(txt(info.get("kind")), DIM)] if info.get("kind") in ("forum", "news") else [])
        note += [("not in this server's list", DIM)] if info.get("kind") == "unknown" else []
        note += [("bot cannot read", WARN)] if info.get("read") is False else [("? not known if readable", DIM)] if info.get("read") is None and info.get("kind") != "unknown" else []
        head = Text.assemble("▸ " if i == at and side == "left" else "  ", (box(g is not None), BRAND if g else DIM), " ", (name(c), "" if g else DIM))
        for s, style in note:
            head.append("  " + s, style)
        head.truncate(lw - 14, overflow="ellipsis", pad=True)
        head.append(fit("" if g is None else "required" if g["mention"] else "any message", 14), ALERT if f"mention:{c}" in wide else "")
        L.append(head)

    below = [Text(), Text.assemble("▸ " if left[at][0] == "dm" and side == "left" else "  ", (fit("DMs", 6), DIM), dms,

    # the right pane, beside the lines above

        else:

        out.append(line)
    out += below   # the DM policy and the mode take the whole width
    for line in out:
        line.truncate(width, overflow="ellipsis")
    return out

def in_terminal(argv: list) -> int:
    """`argv` run on the terminal the TUI has let go of (App.suspend), then one line read, so what it printed stays
    until it was read. Its exit status; 127 when it cannot be started, 130 after Ctrl-C."""
    try:
        rc = subprocess.call(argv)
    except OSError:
        rc = 127
    except KeyboardInterrupt:
        rc = 130
    try:
        input(f"\n[exit {rc}] enter goes back to the claude-discord tui ")
    except (EOFError, KeyboardInterrupt):
        pass
    return rc

        try:
            with self.suspend():

## Who may drive a bot: `access`

Which channels a bot listens in, who may write to it there, whether it needs an
@mention, who may DM it, and its mode are read and changed with one verb
(1.13.0). The TUI's access editor (`e` on a bot row) is a front for it and
changes nothing any other way.

```sh
claude-discord access <bot> --json            # the policy, the server's channels, the people known: one line of JSON
claude-discord access <bot> set <change>...   # shows what would change, asks, writes
```

| change | does |
|---|---|
| `channel+<channel id>` | the bot listens there: an @mention required, from the owner (`DISCORD_USER_ID`) alone |
| `channel-<channel id>` | it stops listening there |
| `mention:<channel id>=on\|off` | an @mention is required / every message is answered |
| `allow:<channel id>+<user id>`, `allow:<channel id>-<user id>` | a sender is added to, or taken off, that channel's list |
| `allow:<channel id>=any` | anyone in the channel may write to it (an empty `allowFrom`) |
| `dm=allowlist\|pairing\|off` | the DM policy. `off` is an allowlist with nobody on it; the plugin's own `disabled` is not offered, because it drops every message, in the channels too |
| `dm+<user id>`, `dm-<user id>` | the DM allowlist: whoever is on it also answers the bot's permission prompts |
| `mode=none\|dev-manager\|autoresearchclaw` | the bot's mode, through `setup <bot> --mode` with its questions answered by Enter (peers and hosts kept) |

A change is a word of lower-case letters, digits and `: + = -`; ids, never
names. The words are applied in order to the file as it is, so every key the
verb does not know (the plugin's `pending` pairings, `ackReaction`, anything
else) stays. `set` prints each change, names resolved from what this machine
keeps (`channel-names`, `user-names`, `peers.json`; a person is shown with the
id, since a display name is the sender's to choose), then asks:

- **one no, anywhere, writes nothing** (exit 4): the file is what was shown and

set of words would do. A removal never empties a sender list (an empty list is
everyone): say `allow:<id>=any` to mean that.

official plugin reads `access.json` at every message, so **a change applies at
the next message, with no restart**; a file it cannot parse it moves aside and
replaces with its defaults (pairing, no channel), which is why the file is
never written in place. The plugin rewrites the file itself, with no lock,
when a DM asks for a pairing code or a code expires: the new file is made from
the file as it is at the moment of the write, and the write is given up (exit
1) when the policy changed while the questions were open. Each write adds a
line to `<bot dir>/access.log`: the time, the local account, the machine and
the change words. A mode change reaches the hooks at their next call; the
dev-manager rule text reaches, or leaves, a running session at its next start,
compact or clear.

`--json` asks Discord, with the bot's own token and on the bot's own machine,

permission that is no number. Never a guess. Only the server of the bot's main
channel is asked.

`<alias>` is a line of the manager's hosts ledger (`local` too: then it runs

| exit | means |
|---|---|
| 0 | done, or nothing to change |
| 1 | it could not: no such bot, `access.json` unreadable or changed meanwhile, a failed write, the lock held 5 s, no manager's ledger for `--host` |

| 3 | no terminal: the changes were printed, nothing written |
| 4 | answered no: nothing written |
| 5 | `--host`: the host did not answer, or its claude-discord is older than 1.13.0 |
